前端里的「脚手架思维」：先搭骨架，再抠细节

木质脚手架发布于 2026 年 8 月 28 日阅读约 2 分钟

带过几个新人之后，我发现一个高频困境：盯着一个按钮的圆角改了四十分钟，页面还是散的。

问题不在审美，在顺序。

什么是脚手架思维

盖楼的顺序是：搭架子 → 浇结构 → 拆模 → 装修。

写界面也一样，只是我们太容易在「装修」阶段流连忘返。脚手架思维概括起来就一句话：

先让东西站得住，再让东西好看。

具体拆成三层：

第一层：结构层

打开编辑器先别写样式，先把 DOM 标签写对：

  • 语义标签用对了吗（header / nav / main / article）？
  • 信息的层级和视觉的层级能对上吗？
  • 有没有把「一行里并排的三样东西」错误地嵌套了七层？

结构错了，后面所有 CSS 都是在打补丁。我通常先写一版零样式的页面，用浏览器默认排版检查阅读顺序——能顺着读下来，结构才算过关。

第二层：布局层

给盒子定位置：容器多宽、栅格几列、间距几档。

这一层我只允许自己用三类属性：flex、grid、gap。颜色、圆角、阴影一律不许碰。布局验收标准也很粗暴：把页面缩到手机宽度，不出现横向滚动。

.layout {
  display: grid;
  grid-template-columns: 1fr 300px;
  gap: 28px;
}
@media (max-width: 920px) {
  .layout { grid-template-columns: 1fr; }
}

十行 CSS，桌面与移动的骨架就都立住了。

第三层：装饰层

最后才轮到颜色、字体、圆角、阴影、过渡。这时候因为前两层是稳的，装饰怎么加都不会翻车——就像墙面平整了，刷漆才会匀。

和「先做再优化」有什么不同

有人会说这不就是「先完成再完美」吗？不完全一样。

脚手架思维强调的是层次之间的单向依赖：

  1. 装修不改变结构；
  2. 结构不迁就装修。

反过来的事故我见过太多：为了某个渐变背景，硬把标题拆成三层 span；为了一个斜切角，把整块语义结构搅碎。这些都属于「先刷漆再砌墙」。

什么时候可以打破它

规则存在的意义是被合理地打破。两种情况例外：

  • 视觉探索期：还不知道这页长什么样，可以先开一个草稿画布随便铺色块；
  • 组件微调：结构已经稳定，只动 border-radius 当然不必重开评审。

但只要涉及到「新增一块内容」，就请回到第一层，先把标签写对。

小结

脚手架是临时的，但它决定了楼能盖多高。

下次打开 Figma 对着稿子发呆时，不妨先别想「这个渐变用几度」，先问自己：

这一页的杆件，都立稳了吗？
